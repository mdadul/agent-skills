# Visitor Examples

## 1) Geometry Shapes — XML Export (Canonical)

### Context
A `Shape` hierarchy (`Dot`, `Circle`, `Rectangle`, `CompoundShape`) is in production and cannot be modified beyond adding `accept`. XML export must be added without touching the shapes.

```typescript
// Element interface — only accept() added
interface Shape {
    move(x: number, y: number): void;
    draw(): void;
    accept(v: Visitor): void;       // the one required addition
}

// Each element calls the MATCHING visitor method — this is the key
class Dot implements Shape {
    constructor(public id: number, public x: number, public y: number) {}
    move(x: number, y: number) { this.x = x; this.y = y; }
    draw() { /* ... */ }
    accept(v: Visitor) { v.visitDot(this); }      // NOT v.visit(this) — must be specific
}

class Circle implements Shape {
    constructor(public id: number, public x: number, public y: number, public radius: number) {}
    move(x: number, y: number) { this.x = x; this.y = y; }
    draw() { /* ... */ }
    accept(v: Visitor) { v.visitCircle(this); }   // specific to Circle
}

// Visitor interface — one method per concrete element type
interface Visitor {
    visitDot(d: Dot): void;
    visitCircle(c: Circle): void;
    visitRectangle(r: Rectangle): void;
    visitCompoundShape(cs: CompoundShape): void;
}

// Operation 1: XML export
class XMLExportVisitor implements Visitor {
    private result = "";

    visitDot(d: Dot) {
        this.result += `<dot id="${d.id}" x="${d.x}" y="${d.y}"/>\n`;
    }
    visitCircle(c: Circle) {
        this.result += `<circle id="${c.id}" x="${c.x}" y="${c.y}" r="${c.radius}"/>\n`;
    }
    visitRectangle(r: Rectangle) {
        this.result += `<rect id="${r.id}" .../>\n`;
    }
    visitCompoundShape(cs: CompoundShape) {
        // Recursion: delegate to each child, then export wrapper
        cs.children.forEach(child => child.accept(this));
        this.result += `<compound id="${cs.id}"/>\n`;
    }

    getXML() { return this.result; }
}

// Operation 2: area calculation — new visitor, zero element changes
class AreaCalculatorVisitor implements Visitor {
    total = 0;
    visitDot(_d: Dot)             { /* point has no area */ }
    visitCircle(c: Circle)        { this.total += Math.PI * c.radius ** 2; }
    visitRectangle(r: Rectangle)  { this.total += r.width * r.height; }
    visitCompoundShape(cs: CompoundShape) {
        cs.children.forEach(child => child.accept(this));
    }
}

// Client — no instanceof, no type checks
const shapes: Shape[] = [new Dot(1,0,0), new Circle(2,5,5,10), new Rectangle(3,1,1,4,6)];

const exporter = new XMLExportVisitor();
shapes.forEach(s => s.accept(exporter));
console.log(exporter.getXML());

const calculator = new AreaCalculatorVisitor();
shapes.forEach(s => s.accept(calculator));
console.log("Total area:", calculator.total);
```

Adding a `JSONExportVisitor` → one new class, zero changes to shapes or existing visitors.

## 2) Geographic Graph — Node Export (Problem Statement Example)

### Context
A graph of `City`, `Industry`, `SightseeingArea` nodes. The system architect forbids modifying these classes. XML export needed.

### Without Visitor (broken approach)
```typescript
// Client must know all types — fragile, not extensible
for (const node of graph) {
    if (node instanceof City)             exportVisitor.doForCity(node);
    else if (node instanceof Industry)    exportVisitor.doForIndustry(node);
    else if (node instanceof Sightseeing) exportVisitor.doForSightSeeing(node);
}
```

### With Visitor (double dispatch)
```typescript
// Added to each node class — the only change
class City { accept(v: NodeVisitor) { v.visitCity(this); } }
class Industry { accept(v: NodeVisitor) { v.visitIndustry(this); } }

// Client — clean, type-agnostic
for (const node of graph) node.accept(exportVisitor);
```

The `instanceof` chain moves permanently into the element classes as a single, correct routing call.

## 3) AST Traversal — Compiler / Linter

### Context
An Abstract Syntax Tree has nodes: `NumberLiteral`, `BinaryExpression`, `FunctionCall`, `VariableRef`. Operations needed: type-checking, constant folding, code generation, pretty-printing.

### Design
- **Element interface**: `ASTNode` with `accept(v: ASTVisitor)`.
- **Visitor interface**: `visitNumber`, `visitBinary`, `visitFunctionCall`, `visitVariable`.
- **Concrete Visitors**: `TypeChecker`, `ConstantFolder`, `CodeGenerator`, `PrettyPrinter`.

Each visitor accumulates its own state (type environment, folded constants, generated bytecode) across the traversal.

### Note
This is the canonical reason Visitor is popular in compiler implementations — operations change as the language evolves, but the AST node types are relatively stable.

## 4) Why `accept(v)` Cannot Call `v.visit(this)` Generically

```typescript
// WRONG — loses the concrete type
class Dot {
    accept(v: Visitor) {
        v.visit(this);  // 'this' is typed as Dot here, but...
    }
}

// If Visitor has: visit(e: Element) — only one method
// Then visitDot, visitCircle, visitRectangle all collapse to one method.
// The whole point of Visitor is separate methods per type. You need:

class Dot {
    accept(v: Visitor) {
        v.visitDot(this);  // CORRECT — statically typed as Dot → right overload
    }
}
```

`v.visitDot(this)` inside `Dot.accept` is the essential step — it's the second dispatch that routes to the type-specific visitor method.

## 5) Visitor Stability Trade-Off

```
Element types: Dot, Circle, Rectangle, CompoundShape  (stable — rarely added)
Operations:    XML export, JSON export, area calc, type check, rendering  (change often)

Cost of adding a new OPERATION → 1 new Concrete Visitor class         ✓ cheap
Cost of adding a new ELEMENT   → 1 accept() impl + 1 new method in
                                  EVERY existing Visitor               ✗ expensive

Flip the hierarchy if element types change often:
  → use virtual methods on elements instead (each element overrides the operation)
  → Open/Closed in the other direction
```

## 6) Visitor + Composite (Recursive Tree Traversal)

```typescript
class CompoundShape implements Shape {
    children: Shape[] = [];

    accept(v: Visitor) {
        // Depth-first: visit children first, then self
        this.children.forEach(child => child.accept(v));
        v.visitCompoundShape(this);
    }
}
```

Client calls `root.accept(visitor)` once. The compound element recursively propagates `accept` to all descendants. Visitor collects results across the entire tree in its instance state.
